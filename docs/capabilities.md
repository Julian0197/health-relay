# 能力覆盖与验收

所有 App 能力当前均为 planned。SDK 清单是覆盖基线，不是完成清单。

目标覆盖公开 HealthKit API、当前系统和应用权限允许读取的类型；不是保证 Apple 健康中的所有派生评分和图表都有公开接口。

| 家族 | 交付目标 | 当前 |
| --- | --- | --- |
| Quantity | 完整可用目录、通用明细、合法统计 | planned |
| Category | 完整可用目录、通用明细、逐类计数/时长 | planned |
| Correlation | 父子结构、通用关联配置 | planned |
| Workout | 核心记录、路线与曲线分页 | planned |
| Activity Summary / Characteristics | 快照策略与比较 | planned |
| ECG / Audiogram / Series | 专用读取与完整子块确认 | planned |
| State of Mind / Medication | availability、结构化读取 | planned |
| Clinical / restricted | 接入条件、独立权限验收 | planned |

## 每个目录项的完成条件

1. 标识符、家族和 availability 正确。
2. 名称、单位/枚举语义正确，原始值保留。
3. 能创建并执行配置；不支持的操作同时在 UI 与导入时拒绝。
4. 对应编码器有合成协议测试。
5. 有数据的真机记录与导出一致；无样本只标 implemented，不标 deviceVerified。

“全选”只选可用且已实现类型；planned 项不能选中后静默丢弃。数量/分类首个版本覆盖后，复杂家族仍明确显示独立状态。

## 引擎验收矩阵

| 场景 | 预期 |
| --- | --- |
| 心率切换体重、营养、步数 | 不修改执行器和上传器 |
| 多数量指标，不同单位 | 相同任务模型，逐项单位校验 |
| 症状与睡眠分类 | 共用分类读取器，保留时间与值 |
| 来源包含/排除 | 排除优先，包含不表示排序 |
| 断网后恢复 | 缓存批次与新保存样本补传，显示覆盖范围 |
| 提交后客户端超时 | 重发同 ID，数据库不重复计入 |
| 分页读取后退出 | 数据与 anchor 同事务，无丢失 |
| 迟到/删除汇总对象 | 只重算相交窗口，替换快照 |
| 跨天分类、时区、夏令时 | 精确窗口，不固定日长 |
| 旧 iOS 导入新指标 | 显示不可用，不错误启用 |
| 空查询 | 不断言拒绝权限，不上传空健康批次 |
| 401/422/413/429 | 等凭据/协议错误/拆批/退避 |
| 没有变化 | 不重新导出历史，仅处理已有队列 |
| 配置复制/更新/禁用 | ID、版本、凭据和检查点隔离 |

首个可用版本是“通用数量/分类目录 + 任务编辑 + HTTP + 增量明细 + 日志”，而不是固定五类任务。后续汇总和复杂数据继续扩展同一引擎。
