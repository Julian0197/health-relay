# 自动化核心能力：汇总、HEA、补传与后台续跑

2026-10-12 核心实现记录。下方测试结果保留当日基线；10 月 13 日继续完成了前台定时、HEA JSON/CSV、独立补传和后台 Shortcuts 调用的真机验收，定时范围见[定时与提醒验收](implementation-scheduling.md)，最新运动/HEA 映射、CSV 和测试范围见[HEA 验收](implementation-hea.md)。

## 怎样配置

1. 在同一个任务中选择数量指标，可同时包含步数、心率、HRV 和睡眠。
2. 导出设置选择“汇总数据”和秒/分钟/小时/日/周/月/年分组。每指标采用目录允许的默认统计；在指标设置中可单独覆盖。累计量默认求和，测量值默认均值/最小值/最大值。旧配置的任务级 `statistics` 仍生效。
3. 接自有接口优先用 HealthRelay JSON；接已有 HEA 接收器可选 HEA JSON v2。当前已有 106 项数量映射和专用数据族；具体支持与未验收边界见 HEA 验收文档，未知项会阻止运行。
4. HEA 格式选择删除处理：默认“停止并提示”；选“跳过删除事件”会推进进度并记录数量，但无法撤回远端旧记录。
5. 在“运行与日志 → 历史补传”选起止时间。补传使用原任务的数据规则和接口，独立保存进度；未完成前阻止修改/删除原任务，避免认证引用失效。可以续跑或取消，取消不撤回已经提交的数据。
6. 正常任务推荐“自上次同步 + 数据变化触发”，按需开启前台检查。“定期检查”默认关闭；开启后保持前台时按期望间隔检查，后台申请 iOS 调度机会，不承诺后台准点运行。

[混合汇总配置示例](../examples/task.mixed-aggregate.json)不含认证值或真实健康数据。复制/导入的任务默认关闭，需在设备绑定认证。

## 汇总怎样保证结果正确

HealthKit anchored query 只用来发现变化。每个变化映射到完整日历窗口，再用 `HKStatisticsCollectionQueryDescriptor` 查询该窗口的完整统计；不是把本次新增记录相加或平均。变化查询覆盖完整窗口和跨界样本，生成的窗口限制在任务范围覆盖的窗口集合内。

- 窗口按任务时区划分，周从星期一开始，DST 日期不假定为 24 小时。
- 原生窗口身份为 `window:<UTC start>:<UTC end>`。服务端按任务/指标/窗口身份 upsert；迟到数据用相同身份覆盖原值。
- 删除有 UUID 时通过本地 UUID→窗口索引定位；索引中没有的删除触发任务范围内逐窗口回查。索引最多 20,000 项，哈希最多 4,096 项，不缓存完整健康明细。回查每次最多 20 个窗口，进度随确认持久化。
- 无变化不会重新查询统计快照，也不会发 HTTP。窗口内容没变化时哈希抑制重复上传。缓存淘汰、重装或日期规则变化可能产生重传，接收端仍需幂等。
- 空窗口是原生 delete。HEA 无删除语义；窗口仍有值时可发送修正值，窗口变空时按显式删除策略处理。
- 汇总查询会扩展到与所选日期相交的完整窗口；不是截取半个小时或半天后仍标成完整窗口。

睡眠独立使用当地中午 12 点到次日中午的窗口，日期归次日；分段与窗口相交后，同阶段重叠去重，总睡眠对所有睡眠阶段求并集。它不是 Apple 健康评分或 HEA 私有睡眠算法的复刻。多个来源对同一时段给出冲突阶段时，各阶段仍独立统计，分阶段之和可能大于总睡眠；需要精确阶段分析时选择单一来源。

## HEA 兼容边界

[官方 JSON 文档](https://help.healthyapps.dev/en/health-auto-export/export-format/health-metrics/)规定心率 `Min/Avg/Max`、普通数量 `qty`、日睡眠日期及阶段字段。本项目采用这些结构，保留已有 HRV/RMSSD 名称映射；体重名称改为官方当前的 `weight_&_body_mass`，使用旧名字的接收器需要适配。

- 原始心率点用相同值填 Min/Avg/Max；汇总心率只输出实际选择并取得的统计。
- 日睡眠时长为小时，`date` 为 `yyyy-MM-dd`，起止时间带时区。
- 百分比按本项目兼容 profile 输出 0–100；尚未用真实 HEA 对照捕获确认数值尺度。
- 自动添加 `automation-name/id/aggregation/period` 和 `session-id`。中文任务名按 UTF-8 百分号编码；重试沿用冻结的 Header、正文和 batch ID。
- `previousDays=7` 对应完整前七天；`defaultRange` 为昨天至今；任意 N 天/custom 使用本项目 `custom` 扩展值。不能认为所有接收器都接受扩展值。
- HEA CSV 按实机中文样本改为每批一张数量/睡眠宽表，使用明确的列顺序、固定输出单位和空单元格。multipart `file` 字段仍是本项目约定；没有真实 REST 捕获，不作完整兼容声明。
- 原生 CSV/Markdown 仍是通用记录表，和 HEA CSV 分开命名。
- HEA v1/v2、血压/运动等已接入；要求多指标整包的接收器尚未支持，当前引擎按指标分页请求。HEA 不保留原始 UUID 和所有 metadata，不等于无损 HealthKit 备份。

## 续跑与后台

所有普通任务、手动运行、读取检查和历史补传共享串行执行门；自动候选按最近尝试时间排序，避免慢任务一直占先。一次自动唤醒共享 25 秒预算，在读取/上传边界检查剩余时间；单次系统查询或网络调用并非硬性 25 秒超时，BGTask 到期会取消当前工作。

一轮任务持久化开始日期和下一个指标，跨午夜继续旧范围，整轮完成后再进入新日期。每任务/补传最多一个待上传批次；建议 checkpoint、聚合索引和哈希随批次一起保存，确认后提交。失败发送不推进已确认游标。Retry-After 支持秒数和 HTTP-date，413 保留批次等待检查，不假装自动拆包成功。

前台检查、数据变化、可选定期补查区分处理。后台刷新仅为 dirty、未完成分页、可重试批次、补传或显式定期补查申请。持久化日志包含触发原因、耗时、各指标确认数量、HTTP 状态和跳过删除数，可导出诊断；不导出 payload 或认证值。

仍使用普通 URLSession。iOS 暂停/终止 App 后不承诺继续发送；重新获得执行机会后从磁盘重试。锁屏健康读取、低电量、系统取消和自然后台唤醒须真机观察，不能从模拟器或代码推断已验证。

| iOS 构建 | 模拟器与签名 iOS target 构建通过 |
| 新功能真机 | 暂未验收，用户使用手机期间未安装新版或修改手机任务 |

Core 集成测试默认跳过外网用例。显式验收时，把 `{"endpoint":"https://healthrelay-acceptance.<your-account>.workers.dev","key":"YOUR_TEST_KEY"}` 放在忽略提交的本地文件，再设置 `HEALTHRELAY_CLOUDFLARE_TEST_CONFIG` 指向它。测试拒绝生产 Worker 命名/路径；不得改用生产 key 或数据库绑定。

Cloudflare fixture 新增 `POST /ingest/hea`、`POST /ingest/hea-csv` 和认证后的 `GET /inspect?taskId=...&type=...`。inspect 只按主键前缀读取最多 5 条，status 读取单条统计，无全表扫描。fixture 只验证所选 profile，不代替真正 HEA 下游服务的兼容验收。
