# 后台生命周期与失败恢复

2026-10-13。目标是任务启用后无需点击通知或运行即可同步。生命周期回归与真实 iPhone 自然后台结果分别记录。

## 本次修复

- 在 AppDelegate 的 didFinishLaunching 中同步安装 HealthKit Observer，后台启动不再依赖 SwiftUI 页面出现。
- Observer 等待本次处理结束再调用完成回调；25 秒到期时取消工作，先申请恢复机会，再恰好一次完成。等待串行许可也不能无限拖住系统回调。
- BGTask 到期同样先安排恢复再完成。运行中的已启用任务和未完成补传保留 60 秒后的兜底申请；实际执行仍检查 Retry-After、最小间隔和当前运行状态。完成后回到正常计划，不持续每分钟扫描历史。
- 受保护数据不可用时暂缓配置读取，不标记为文件损坏，不根据空任务清除后台订阅。系统报告数据可用或 App 回到前台时重载；tasks/backfills 全部成功后一起发布。真实解码或版本错误继续阻止保存。
- 保留本地文件和 Keychain 的既有保护等级；解锁不意味着 iOS 必然立即唤醒 App。

## 回归证据

- 真机启动诊断：修复前 didFinishLaunching 为 0/4 个 Observer，修复后为 4/4。`scripts/check_background_startup.py` 可对 DEBUG 元数据重复断言；只证明启动注册顺序。
- 本轮本地 Core 回归为 73 项通过、1 项可选外网集成跳过；此前 74 项含外网的通过记录保留为历史证据。
- 8 项原生 iOS 单元测试通过。先复现提前 completion、到期未取消、到期未安排恢复、配置半加载与不可用数据仍被读取，再修复。保护状态由注入的 availability 模拟，文件读写使用独立临时目录，不能替代真机锁屏验证。
- 本轮配置保存/重启与前台到期自动检查 UI 回归通过；最终兜底调度修改后又复核前台间隔用例。8 项接收器 Node 测试通过，签名真机构建通过。
- 测试接口支持有认证、指定任务、有次数/有效期上限的一次 503 注入；尝试日志只记录批次 ID、正文摘要、HTTP 状态、条数与时间，不输出健康值或密钥。

## 真机无人干预验收

最终候选包已安装。17:07 回主屏幕后，对原隔离测试任务安排一次 503，30 分钟自动过期，重试等待 30 秒。观察期间不打开 HealthRelay 或点运行。17:14 从系统设置确认全局后台 App 刷新允许无线局域网与蜂窝数据，未修改设置。

待确认：后台执行时的 appState、自然事件来源、同批次 503 到 200 自动恢复、相同正文摘要及最终仅提交一次。没有这些证据前，不把本轮称为自然后台失败恢复已通过。

既有 15:10 healthChange 自动运行记录和 15:12 系统 Shortcuts 时间触发保留为独立证据，见[定时与提醒验收](implementation-scheduling.md)。它们不替代本轮恢复，也不证明强退、长期挂起、锁屏或低电量的持续可靠性。

Apple 要求启动阶段注册 Observer，并在处理完成后调用回调。参考 [Executing observer queries](https://developer.apple.com/documentation/healthkit/executing-observer-queries)；后台刷新时机由系统决定。
