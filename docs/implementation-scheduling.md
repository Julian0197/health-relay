# 定时、快捷指令与提醒：实现和验收

2026-10-13。当前已补上持续前台定时、后台 AppIntent 和独立提醒。部分链路通过真机验收；系统时间触发、通知自然送达和自然后台唤醒仍未完成，不能称为 HEA 全功能对等。

## HEA 对照

| 能力 | HealthRelay 当前行为 | 验收状态 |
| --- | --- | --- |
| 期望同步频率 | 1 分钟至 7 天；前台到期检查，后台申请 iOS 运行机会 | 真机前台间隔执行通过；后台不保证准点 |
| App 持续打开时运行 | 单个可取消的唤醒任务，到期检查、按最新状态重新安排 | 真机与模拟器均验证无需导航或手动运行即可再次检查 |
| 数据变化触发 | Observer 标记相关任务，最小间隔和重试退避生效 | 实现与核心调度测试通过；自然后台延迟待测 |
| Shortcuts 时间自动化 | “运行健康导出”可在 App 不在前台时执行，返回文本，无需点击完成 | 真机在 Shortcuts 内调用通过；系统时间触发尚未验收 |
| 提醒 | 每小时、每天、指定星期，使用手机当地时间 | 日期/DST 与配置重启恢复测试通过；真机通知待测 |
| 通知“打开并同步” | 前台打开已有启用任务，使用现有引擎；关闭、删除、正在运行时回列表 | 代码与构建通过；冷/热启动及前台回调交互待测 |
| 锁屏准点读取上传 | 不作保证；本地文件、Keychain 和 HealthKit 受锁定状态限制 | 尚未做锁屏系统时间触发验收 |

HEA 官方也把频率定义为期望值，说明 App 保持打开时会运行自动化，后台无法保证精确时间；提醒自身不会执行任务。见 [Automations](https://help.healthyapps.dev/en/health-auto-export/automations/) 和 [REST API](https://help.healthyapps.dev/en/health-auto-export/automations/rest-api/)。每天某时运行由系统 Shortcuts 个人自动化触发，仍需要可读取健康数据的解锁状态，见 [Schedule Automations Using Shortcuts](https://help.healthyapps.dev/en/health-auto-export/automations/schedule-automations-using-shortcuts/)。

## 使用方式

- 持续前台定时：在任务编辑页开启“定期检查”，设置“期望间隔（分钟）”，保存并启用任务。后台交给 iOS 调度，不保证固定延迟。
- 每天某时执行：先在 App 中完成健康授权、配置并启用任务；在系统 Shortcuts 创建“特定时间”个人自动化，添加 HealthRelay 的“运行健康导出”并选择任务。HealthRelay 不自行创建或修改用户的个人自动化。
- 独立提醒：进入“安排提醒”，选择频率/时间/星期并请求通知权限，返回任务页保存，再启用自动化。普通通知点击查看任务；“打开并同步”请求执行。提醒不是任务完成通知，后台已经同步后仍可能出现。

Shortcuts 入口要求设备本地认证，不强制切换到 App 前台，也不展示需要点击完成的结果弹窗。任务关闭时拒绝运行；待上传批次遵守 Retry-After 和“只允许人工重试”。用户在 App 里点“立即运行”仍可以主动重试关闭任务。提醒的显式“打开并同步”也走用户主动运行语义。

## 调度和状态

`AutomationSchedule.nextDate` 统一计算前台唤醒和 BGTask 的候选时间：待上传批次重试优先；未完成读取与补传继续运行，读取失败至少延后 5 分钟；普通任务使用上次尝试时间加期望间隔。未开启定期检查、没有新变化或续跑需求时，不安排固定历史扫描。

前台仅保留一个唤醒 Task，退出前台即取消，配置/执行状态改变时重新计算。普通任务和补传继续共享 25 秒预算、串行许可和按上次尝试时间排序的队列。无新数据不发空请求。无关 HealthKit 回调不执行仅启用定期检查的任务，避免错误归因为 healthChange。

提醒是可选 `execution.reminder`，旧配置缺少该字段仍可读取；提醒和执行偏好不参与同步身份，不重置 anchor。每次保存、启停或删除后重建本 App 的提醒请求，关闭或删除任务不再排入提醒。通知权限被拒绝时，编辑页显示当前状态并提供系统设置入口。

## 验收证据

- 74 项 Core 测试通过：55 XCTest（含真实隔离 Cloudflare 集成）和 19 Swift Testing。新增覆盖最小间隔、不漂移、不主动轮询、续跑失败退避、回调隔离、提醒日期/DST、旧配置兼容、快捷指令重试约束。
- 5 项原生模拟器 UI 用例分别通过：通用任务保存恢复、503 后重启重试、汇总与独立补传、保持前台到期自动检查、提醒保存后重启恢复且任务仍关闭。提醒用例使用无认证任务，避免未签名模拟器的 Keychain 权限限制；测试明确检查保存失败弹窗和编辑页关闭。
- 最终 iPhone 签名构建通过。最终启停/退避修复尚未重新安装到手机。
- 真机真实健康数据发送到独立 Cloudflare 测试接口：HEA JSON 首次确认 2 条/2 批，CSV 确认 2 条/2 批，独立补传确认 5 条/5 批；前台定时随后出现无新数据结果，以及新数据到达后的 1 条确认。
- 真机在 Shortcuts 内调用成功，HealthRelay 未切至前台，日志记录 `shortcut`，返回无新数据文本；这不是系统时间触发验收。该测试早于最后的任务启停与退避修复。

接收端回执证明测试接收器已接收并提交这些格式，不证明与 HEA 自身导出文件逐字段完全相同，也不替代对 HealthKit 汇总数值及多来源睡眠语义的独立核对。此前 5 项接收器 Node 回归通过；本轮未修改接收器。未向既有生产接口写入，未修改原 HEA 自动化。

## 尚待真机完成

手机在通知验收前断开 USB 连接。恢复连接后需要：安装最终包；验收系统时间自动化、锁屏/解锁行为、通知自然送达、普通点击和“打开并同步”的冷/热启动、关闭/删除后的提醒清理；检查通知打开与 onForeground 同时到来是否产生额外运行；关闭临时一分钟验收任务。自然 BGTask 延迟与后台限制仍需独立观察，不以构建或模拟器通过替代。
