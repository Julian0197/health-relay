# 服务迁移来源与验收

本次把 `watch_monitor` 的已提交服务与自动化规则迁入 HealthRelay，提供可部署、可调试的完整链路。**代码迁移已完成；原生产环境和手机上的任务没有切换。**

## 来源与范围

- 服务来源：用户提供的 `watch_monitor` 仓库提交 `97a4d36`，目录 `integrations/hae-webhook/`。不包含源工作区未提交的变更、历史私有文档、真实健康数据或部署文件。
- App 基线：HealthRelay `3fb5857`，包含锻炼及扩展 HAE JSON 的实现。本次新增服务配置及跨语言契约测试，未改动 App 的执行引擎。
- 保留五流接收、SQLite 事实存储与去重、Alarm 调度、压力及睡眠计算、签名文案、Base 发布、加签群卡和 HTML 看板。
- 公开化改动：移除账号及资源绑定；示例任务默认关闭；看板设备名改为通用描述；重新打开链接改为可选 HTTPS 配置；私有 HTML 输出受忽略规则、路径检查和文件权限约束。
- 五份 JSON 保留原规则的指标、汇总粒度、时间范围和期望最小间隔。它们来自已提交契约，未在本轮重新读取手机上的 HAE 配置。

第三方前端依赖仍遵守各自许可证；HTML 构建同时输出 `dist/licenses.txt`。源服务来自同一使用者提供的项目，本次不搬运其他产品的二进制或素材。

## 仍需独立验收

1. 将五份配置导入实际 iPhone，用相同来源、时间范围和单位逐项对照 HAE；确认权限、手动运行、失败重试及历史补传。
2. 验证来源绑定后才启用压力评分。心率汇总缺少 source，HRV 报告 HealthRelay，睡眠保留原始来源；当前不能自动证明它们来自同一设备，详见[来源说明](automation-profile.md)。
3. 在自己的测试环境配置 Cloudflare Secrets、飞书群和展示 Base，分别验收入库、群卡、Base title、个人签名及读者页面。源环境未迁数据、未换群、未重置 namespace。
4. 验证妙笔 HTMLBox 的真实运行时授权。`401 Request ticket required` 或 `403 Document context mismatch` 指向平台请求凭证或文档上下文校验；现有前端可能将其笼统显示为“没有访问权限”。Base 能读取不代表 HTMLBox 会话正常，单元测试不覆盖平台发行版本变化。不要以扩大分享权限来绕过此类错误。
5. 完成 Watch 真机配对、本机认证、独立上传、自然后台触发及连续运行。iPhone Use 的前台操作和模拟器截图不证明这些行为。

锻炼样例先传摘要；路线、关联曲线、迟到详情补齐和真实 HAE 文件逐项对照仍需专项验收。CSV 的组织方式也不应从 JSON 契约测试推定一致。
